# Themes

A theme document is the creative brief for one benchmark theme.

## File shape

The filename without `.md` is the theme id. The first level-one heading is the player-facing title. Use that heading once at the start of the file.

Short theme documents usually use prose briefs. Longer briefs can use headings or lists to organize their details. Theme documents do not need a fixed section structure, checklist, or word count.

## Content

Most existing themes establish these parts of the intended level:

- a central premise, place, journey, or visual rule;
- the player's relationship to the world and its threats;
- a visual identity, often through palette, light, material, scale, or motion;
- a progression across the run and a final payoff; and
- a musical character that belongs to the same idea.

These parts can overlap. A theme does not need a separate paragraph for each one, and it does not need a boss when another ending fits the premise.

Lead with the player-facing experience. A theme may be specific about a defining image, interaction, rhythm, transformation, or ending when that detail carries the idea. Leave routine implementation choices to the entrant unless they are central to the theme.

Short briefs usually leave exhaustive enemy rosters, tuning values, exact HUD copy, and bar-by-bar arrangements open. Longer briefs may specify some of these when the details carry the theme. Theme documents describe what to create, not how source code should be organized.
